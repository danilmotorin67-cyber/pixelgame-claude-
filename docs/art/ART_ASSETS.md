# Графика для PixelLab: что генерировать и сколько это стоит

Полный перечень собирается из данных игры скриптом `python3 tools/art_manifest.py`
(перезапускайте его после изменений в `data/`). Скрипт пишет:

- [`assets.csv`](assets.csv) — каждый ассет: группа, id, название, размер, число
  картинок, метод PixelLab, приоритет и черновой английский промпт;
- [`animations.csv`](animations.csv) — каждая анимация: цель, действие, число
  направлений, кадры, метод и приоритет;
- [`summary.json`](summary.json) — итоги по группам.

Стиль для всех промптов: пиксель-арт, вид 3/4 сверху, тайл 16×16, герой 16×32,
свет слева сверху, выборочная тёмная обводка в 1 px, палитра «Солёный свет» из
48 цветов (раздел 31 `full.md`, [`ART_DIRECTION.md`](../ART_DIRECTION.md)).

| Статичная графика | 2 286 | 11 430 |

| без опциональной кастомизации героя и набросков (−144 изображения) | | ≈ 23 610 |

Допущения варианта A: персонаж в 4 направлениях считается как 4 изображения,
тайлсет и панель интерфейса — как одно изображение за вызов, анимация — 20 за
каждое направление.

### B. С экономией через возможности API

В документации PixelLab API (v2) есть два механизма, которые сильно удешевляют
массовую графику:

1. **Пакетная генерация объектов** (`create-1-direction-object`): один вызов
   стоит 20–40 генераций. При размере до 42 px он возвращает **до 64 разных
   объектов** (каждому можно задать своё описание), до 85 px — 16, до 170 px — 4.
   Иконки, реквизит, культуры, декор, знаки могил и значки интерфейса (~1 490
   картинок) укладываются примерно в 37 вызовов.
2. **Шаблонные анимации** (ходьба, покой, удар, перекат): **1 генерация за
   направление** вместо ~20. Таких в списке 284 направления.

| | Объём | Оценка |
|---|---:|---:|
| Пакеты ≤42 px (по 64) | 19 вызовов × ~30 | ≈ 570 |
| Пакеты ≤85 px (по 16) | 18 вызовов × ~30 | ≈ 540 |
| Остальное штучно (персонажи, здания, тайлсеты, портреты, иллюстрации) | 798 × 5 | ≈ 3 990 |
| Шаблонные анимации | 284 × 1 | ≈ 284 |
| Анимации по описанию (инструменты, эффекты, станки, боссы) | 361 × 20 | ≈ 7 220 |
| **Всего** | | **≈ 12 600**, с запасом 40% ≈ **17 500** |

Вариант B верен, если «токен» у вас совпадает с «генерацией» в API. Это стоит
проверить на пилоте: один пакет иконок и одна шаблонная ходьба сразу покажут
реальный курс.

## 4. Как генерировать

1. **Сначала пилот P1.** Проверить в игре: читается ли герой 16×32, стыкуются ли
   тайлы, держится ли палитра. PixelLab создаёт персонажей от 16 до 128 px, но
   16×32 — нижняя граница, на ней детали могут «плыть». Если результат слабый,
   поднимаем масштаб персонажей (например, 24×40) и оставляем тайл 16.
2. **Закрепить стиль.** Во всех вызовах передавать `color_image` с 48 цветами
   палитры (`force_colors`), а первые одобренные ассеты — как `style_images` и
   референсы для остальных.
3. **Портреты:** одна база на персонажа, эмоции — правкой этой базы
   (`edit-image`), чтобы лицо не менялось между эмоциями.
4. **Персонажи:** `create-character-with-4-directions`, затем анимации через
   `characters/animations` (шаблон, где возможно) — так направления и цвета
   остаются согласованными.
5. **Тайлы:** `create-tileset` (переходы Wang 16×16) для каждой пары
   поверхностей, сезонные варианты — от одной одобренной версии.
6. Готовые PNG складывать в `assets/` и подключать вместо процедурной отрисовки
   (`scripts/world/*_art.gd` и `_draw` объектов) — это отдельная работа в коде
   после генерации.

Сейчас API PixelLab отвечает, что подписка в статусе `trial`
(`generations: 1.0`, `total: 40.0`), денежный баланс — 0 USD. Для полного объёма
нужен тариф с нужным запасом генераций.
